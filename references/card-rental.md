# 要素卡：转租·招室友（card=`RENTAL`）

## 1. 归属与徽章

| | 供给侧（我有房间） | 需求侧（我找房） |
|---|---|---|
| 覆盖 | 整租转租 / 短租 / 合租招室友 / **住宿预订转让**（酒店房券、单晚住宿——0811 拍板归本卡） | 找房 / 找室友 / 蹲转租 |
| 徽章 | **转租**（合租形态可显**招室友**） | **找房** |
| tradeType | SELL | BUY |

🔴 读侧容错：线上"招室友"常被发成 BUY 且 price=月租**要价**——读方向和价格
**以标题/正文语义为准**（"招/直租/转租出"=供给；"求/收/蹲"=需求），帖型仅参考。

**住宿预订转让子条款**（酒店房券/单晚住宿走本条，不套月租口径——照通用档执行
会问出"月租多少、押金多少、看房时间"三连错位）：
- 计价周期 = **按晚**，走计价行（「£120/晚」），`--price` 填每晚价，
  月租/押金/看房时间一概不问；
- 🔴 必须成立项替换为：**位置（城市 + 酒店/门店名）+ 入住/退房日 + 每晚价 + 币种**
  ——位置**不能跟着月租一起被替换掉**：§5 的匹配主键仍是位置×时间窗，
  不写门店买家根本搜不到（回归仿真实证：只说"洲际"得靠追问补城市）；
- **标签与骨架同步换**：标签用 `#短租 #酒店 #房券`（**不要挂 `#室友`**，
  §5 的固定标签是给转租/合租用的）；描述首段顺序改为
  **酒店与门店——每晚价——入住/退房日——可转让方式**，跳过"房型家具/合租现状"那些行；
- 有效期止填 `--available-until` 并套硬时间窗口径——**过期 = 帖必作废，
  直接建议下架**（实测已有过期 5 天仍在售的房券帖）；§4 的三个时间
  对单晚房券收敛为这一个日期；
- 确认门回显行加：**有效期｜可转让方式**（转姓名？需原订单人操作？）。

## 2. 要素三态表

| 档 | 供给侧 | 需求侧 |
|---|---|---|
| 🔴 必须成立 | 位置（**区域/地铁站级即可发**）、月租+币种 | 目标区域、预算 |
| 尽量抽取 | 租期起止、房型（几室/几人间/家具）、**含不含 bill（必写清，跟月租一起说）**、押金、可入住日、**合租现状**（其他房间住着谁——最易被当闲聊丢掉，仿真实证） | 入住时段、租期长短 |
| 强烈建议补充（卡上标注理由，不追问） | 位置到楼/公寓名（"精确到楼更容易被联系"）、**转租合法性**（"写一句'中介/房东已同意'找房的人更敢联系"——线上 0 提及，问会比市场重）、**看房时间**（"写了看房时间，来的都是认真的"） | 硬性要求点名（独卫/可养宠——"写清省得两边白聊"） |
| 提了才写（绝不主动问） | 室友偏好（性别/作息/宠物/吸烟）、**自我画像**（作息/职业/爱好——真房帖标配，主人自述才写）、break clause/签约对象、朝向采光/通勤/周边 | 自我画像（找房侧它就是"简历"）、**中介过滤**（"中介勿扰/欢迎房东"） |
| 禁问 | 转租原因细节、原始合同/原始租金、房东是谁、"为什么这么便宜" | 预算合理性不评价 |

## 3. 价格语义与计价行

- **周期价**，🔴 **必须带周期单位**——英国惯例按周报价（pw）。
  **`pw` / `pcm` 语境一律默认 GBP**（英式租房行话，线上真实帖写"300pw"不带币种是常态），
  不必为币种追问一次：
  - 写侧：主人说"一周 375"→ 当场换算并**陈述式确认**（不给选择题——`--price`
    必须填月租数，没有"按哪个挂"可选）：「我按月租 £1625 挂，描述里写清
    =£375/周，行吗？」，`--price` 填**月租数**，描述价格位写全：
    「£1625/月（=£375/周），含 bill」；
  - 读侧：见 `pw / per week / 周` 一律按周价理解并换算月价转述，**不裸报 price 字段**
    （评估实证：375pw 被读成月租 = 4.3 倍错）；
- 押金单列（"押一付一"原样写）；需求侧 price = 月租预算上限；需求侧预算同样
  常按周报（线上真实帖有"预算300pw"）——同款换算陈述式确认后 `--price` 填
  **月预算数**，描述写清周口径。

## 4. 时间语义

**区间**（起—止），三个时间别混：可入住日 ≠ 租期止 ≠ 帖子时限。
`--available-until` 填招租窗口截止（如房主离境日）。
🔴 需求侧"求 9.6–9.14 短租"这类**入住窗口已过 = 帖必作废**——按硬时间窗口径
直接建议下架，不问"还找吗"。

## 5. 匹配主键与标签

**位置 × 时间窗**（"9 月入住 Zone 2"），不是关键词——品牌型号逻辑在本卡完全失效。

- 标签固定：`#转租 #室友 #短租 #租房`（需求侧 `#找房 #室友`）；
- 位置词写全变体：区名+邮编+地铁站，**多词连写**（zone2 不留空格）；
- 时间词进标题（"9 月入住"）——检索是字级模糊，月份词是找房人第一搜法；
- 搜法配方（读侧）：区域词 × 时间词 × 形态词（转租/短租/室友/sublet）各一遍混排。
- 🔴 **`--card RENTAL` 筛完必须补一轮无卡关键词混搜**：导入器不判卡，租房语义帖
  大量落在 GOODS——0812 实测搜"租房"150 条里就有 5 条（求 8 月租房、"1000pm 求租房"、
  求租 1b1b、White City 合租房、找室友），只按卡筛会静默漏掉它们。

## 6. 描述骨架

```
供给侧（我有房间）
首段（接头关键信息行，固定顺序）：
  位置——月租（周期+含bill）——租期起止——可入住日——房型家具
次段（条件与现状）：
  合租现状 · 转租合法性 · 押金 · 看房时间 · 室友偏好 · 自我画像
尾段：#标签

需求侧（我找房）
首段：目标区域——预算（**带周期，按周报的换算成月并写清周口径**）——
  入住窗口（起止）——租期长短
次段：硬性要求（独卫/可养宠/近站） · 自我画像（找房侧它就是简历） ·

```

## 7. 确认门回显行（接头卡）

位置（缺楼栋标注"补上更容易被联系"）｜月租+周期+含bill｜租期｜可入住｜房型｜
现状（合租/合法性，缺合法性标注建议句）｜偏好｜押金（缺=标未知）｜照片状态。
点头才发；「强烈建议补充」项带理由摆卡上，主人自己决定。

## 8. 合规与照片检查

- **合法性平台不背书**：描述里"中介已同意"是转租人自述，agent 不核实合同、
  不替任何一方打包票；
- **不碰钱**：押金/租金线下自行处理；英国 deposit protection 常识**可提醒不可承诺**
  （"押金安排你们俩当面说清"，不给法律意见）；
- 🔴 **房间照片是全场景敏感重灾区**（仿真实拦两类）：亮着的屏幕（聊天窗口可读）、
  **合租室友的私物/人像入镜要单独问一句**；快递单/证件照常查；
- 毕业清屋联动：转租与清仓常同时发生——任一侧建档顺口问另一侧，一次托管两帖。
