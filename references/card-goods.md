# 要素卡：二手出售（card=`GOODS`）

## 1. 归属与徽章

| | 供给侧（我出闲置） | 需求侧（我想收） |
|---|---|---|
| 覆盖 | 单品 + 合集清仓（毕业清屋/搬家打包） | 实物求购（「帮我盯着」也走这里） |
| 徽章 | **出闲置**（合集可显**清仓**） | **求购** |
| tradeType | SELL | BUY |

🔴 读侧容错（口径同 marketplace.md §B）：方向以标题/正文语义判（"出/转/清"=供给、"求/收/蹲"=需求），tradeType 仅参考。

## 2. 要素三态表

| 档 | 供给侧 | 需求侧 |
|---|---|---|
| 🔴 必须成立（问一句不占额度） | 品名（品牌/型号/规格——"杯子"不合格）、币种（无符号必问不默认） | 要什么（品名+可接受范围，"Kindle 或同类电纸书都行"）、币种 |
| 优先消费追问额度（≤2 问先花在这） | 面交地点到楼、能否正常用（数码家电图判不了时） | ——（求购侧不追问，缺了照发） |
| 尽量抽取（缺标「未知」照发，不为它问） | 价格（图价/口述价按 intake §2.1.2：图上有标价=已定价，不再建议）、成色（保守判）、瑕疵（图上看得见的**必写**，硬规则）、交易方式（不默认自提）、时限、打包价（合集主动问一句"整套算多少"） | 预算上限、时限、地点、🔴 **最早可取日/到达日**——0811 挖掘的 BUY 帖 TOP1 缺口（17% 求购帖带这个维度）："9 月才到伦敦"决定这单谁能接 |
| 强烈建议补充（卡上标理由，不追问） | 勾邮寄时：邮费谁出+付款顺序（"写清省掉九成邮寄扯皮"）；高价数码见类目表 | —— |
| 提了才写（绝不主动问） | 可预留至 X、多段交接窗口、定金规则（见【交易】行清单） | 用途、品牌偏好、最低成色、应答要求（"来询请附图价"）；"最好是 XX"=**软偏好**，原样带上不追问；"能送到更好"**不硬化成 delivery 枚举**——会筛走只肯面交的卖家（仿真实测），只进描述 |
| 禁问（提了才记） | 购买年份、原价、离境日、配件齐不齐、尺寸重量、包装还在不在 | 用途不盘问、预算合理性不评价 |

> 数据注（0811 prod 全量 991 条核对）：禁问项用户**自愿写**的比例相当高——尺寸/重量
> 25%、可小刀/议价 26%、离境日 17%、配件 11%、原价 8%。**禁问 ≠ 禁写**：图/文里
> 出现了必须抽取落位（口述落位工序），禁的只是开口问——别按"信息覆盖率"推翻它。

**类目要素**（按品类触发，不进通用档）：

| 品类 | 要素 | 档位与理由 |
|---|---|---|
| 服饰 | 尺码 + 卖家上身参考（"163cm 偏瘦供参考"） | **提了必写**——真实服饰帖标配、买家判合身主依据；**身材信息绝不主动问** |
| 小家电/数码 | 插头制式（英标/中标/带转换头） | 尽量抽取——图上认得出就写；买错制式 = 不能用 |
| 高价数码（手机/平板/电脑） | 解绑承诺（iCloud/账号已抹除）、可验证渠道（可当面验机/平台验证） | 强烈建议补充——标注"写一句成交更快"，不追问 |
| 家具大件 | 谁搬（自行搬运 / 可帮搬及条件） | 尽量抽取 |

**合集帖帖级 `--condition`**：逐件成色进分件清单行（§6），帖级字段按
**最保守的一件**填或留空——不做逐件平均。

## 3. 价格语义与计价行

- **一口价**，无计价行——£30 就是总价；可议价与否只进描述（"可小刀"进【交易】行）；
- 图上有标价 = 用户已定过价：直接建档注明「（图上标价）」，不做行情分析不评价；
  币种按图上符号直采，只有数字认不出币种必问（不占额度）；
- 合集 `--price` 留空（面议）或填**打包价**，单件价格写进分件清单行（见 §6）；
- 需求侧 🔴 三个字段翻转（marketplace §A2）：`--price`=**预算上限**（"预算 £50 以内"
  不是"卖 £50"，话术必须翻转）、`--condition`=可接受最低成色、`--photo-url`=
  「大概长这样」参考图——**没有就别硬凑**。

## 4. 时间语义

**截止点**。原话/原帖有日期就填 `--available-until`，别用默认 +14 天；
「可预留至 X」提了必写（跨档期成交钥匙）；多段窗口原样写清，字段仍填最早截止。
需求侧：时限（"月底前要"）过了 → 问一句要不要下架（不是硬作废）；
**到达日**是需求侧特有维度——"人还没落地先蹲货"是 BUY 帖主流形态之一。

## 5. 匹配主键与标签

**关键词/品牌型号**（教材=课程代码、自行车=型号，可检索性最强的两类）。

- 品名中英+长短变体各写一次（「戴森 Dyson 吸尘器」）；买家最可能打的**短词**进 `#标签`（精确通道）；多词连写；
- 🔴 合集：**没写进清单的件搜不到，等于没挂**——每件品名逐行成立（A 档按件生效）；
  需求侧标签里品名中英短词是命门——卖侧上架后反查求购全靠它命中。

## 6. 描述骨架

```
供给单品：四问顺序（intake §2.0）——是什么——什么状况——多少钱——怎么交易；
　"适合谁"必写；【交易】行；尾行 #标签
需求侧：一句"要什么+可接受范围"——预算/时限/地点/到达日——用途（提了才写）——#标签
```

**【交易】行高频清单**（0811 从 1143 条真实帖挖出——用户常写、此前无引导，
AI 代写的帖子不该比手写的信息更穷）：

| 信息 | 处理 |
|---|---|
| 可预留至 X（"9 月新生可留"） | 提了必写——跨档期成交钥匙 |
| 多段交接窗口（"8.8-8.10 或 8.24-8.26"） | 有几段写几段原样写清 |
| 定金/预留规则（"跑单不退"） | 提了必写；🔴 如实转述，**不代收、不背书、不替双方设计定金方案** |
| 结算方式/可收币种（"可 rmb 付"） | 提了必写；标价币种 ≠ 可收币种，别混 |
| 邮费谁出 + 付款顺序 | 勾邮寄就强烈建议补充（"写清省掉九成邮寄扯皮"），不追问 |
| 送货/帮搬条件（"超 £4 送到地铁站"） | 提了必写，门槛/范围原样带上 |
| 先到先得/优先规则（"直取优先""打包优先"） | 提了必写；议价接待时按它排序转述 |
| 清洁承诺（"出前消毒"）、代卖声明（"帮朋友出"） | 提了才写/读到必落——一句话的信任加分 |

**合集 = 分件清单约定**（双方 agent 共守的读写格式，写歪对面读不出）：
一件一行、行首编号，行内固定「品名（叫法变体）——价格 · 成色/瑕疵 · 逐件例外 · 状态」；
🔴 **编号一经发布不重排**——卖掉的行保留原号标 `❌已出`，后补的件续号；
打包价**固定放清单末行**；逐件不同的信息落各自行，"整体八成新"不合格；
**目录留白合法**（0811 实测 7–10% 清仓帖在写）：主人说"还有没拍的"就尾行加
「清单外仍有杂物可询 / 可上门自选」，不逼主人拍全家底。

## 7. 确认门回显行（托管清单）

供给：品名｜价+币种｜成色｜瑕疵｜地点｜交易方式｜时限｜照片状态——
「强烈建议补充」项带理由摆卡上（解绑承诺、邮费谁出），主人自己决定；
合集逐件一行、编号与帖内清单一致。点头才发。
需求：要什么｜预算｜时限/到达日｜地点，缺的标「未知」；🔴 **发布后固定动作 =
反查在售**（§A2 镜像）：命中→按呈现纪律推荐"现货里有几件合适的要不要先看"，
零命中→轻描淡写报一句搜过哪些词。供给侧镜像动作 = 上架后反查求购。

## 8. 合规与照片检查

- 不碰灰色品类：代写代考、账号、药品、酒精烟草；
  有保修/实名绑定的设备**不承诺任何保修转移**的说法；
- 店铺水印/模特街拍 = 商家营销帖，按 intake §4 剔除，不代发；
- 照片敏感检查（公共工序）本帖型重点：快递单、学生证、亮着的屏幕（聊天窗口可读）；
  合集帖图多逐张过，拼图标价表里混入的截图页脚/水印不进描述。
