|---|---|---|
| 覆盖 | 上门代喂 / 住家寄养（宠物到我家） | 求代喂 / 求寄养 |
| 徽章 | **宠物照看** | **求代喂** |
| tradeType | SELL | BUY |

## 2. 要素三态表

| 档 | 供给侧 | 需求侧 |
|---|---|---|
| 🔴 必须成立 | 宠物类型与限制（只接猫/不接大型犬）、服务时段、形态（上门代喂/住家寄养）、计价（§3）、区域 | 宠物情况（种类/年龄/性格）、时段（离境—返程）、报酬 |
| 尽量抽取 | 频次（每日一次/两次）、**报平安约定（每天发照片/视频）**、寄养环境（有无别的宠物/是否封窗） | 频次要求、喂食细节（粮/药）、报平安要求 |
| 强烈建议补充（卡上标注理由，不追问） | 接不接特殊情况（需喂药/幼猫——"写清接不接，省得聊到一半才发现接不了"） | 宠物性格与注意事项（"怕生/会冲门口——写了照看的人才敢接"） |
| 提了才写（绝不主动问） | 钥匙交接方式（**提了必写**——面交/密码盒/邻居转交，接头核心信息）、经验自述（自养几年） | 钥匙交接安排、家中监控告知（有摄像头要说） |
| 禁问 | 客户家精确门牌（区域/楼级即可，接头后私聊） | 出行原因、行程细节 |

**报平安约定尽量抽**：真实帖高频信任要素——"每天发照片/视频"是双方最认的
凭证，图/文里带了必须落进描述，主人顺口说了别当闲聊丢掉（口述落位核对覆盖）。

## 3. 价格语义与计价行

- **按次/按天双结构**（代喂按次、寄养按天），走 marketplace.md §A3 计价行约定：
  - 写侧：`计价：上门代喂 £8/次，每日一次；住家寄养 £15/天，粮自备`；
    `--price` 填起步价（单次/单天数）；
  - 读侧：按结构×时段换算转述（"代喂一次 £8，你出去两周每天一次约 £112"），
    不报裸数；
- 需求侧 price = 愿付报酬（总价或按天，注明口径）。

## 4. 时间语义

**硬时间段**（离境日—返程日区间），不是持续可约：

- 需求侧时段是硬窗——🔴 返程日已过 = 帖作废，直接建议下架，不问"还需要吗"；
- 供给侧写可接时段（"12 月整月在伦敦可接"）；
- **假期档期背景**：圣诞/复活节回国潮是本卡脉冲——需求井喷，供给
  （留守的人）同步放量，节前 2–4 周是发帖窗口，agent 聊档期时带上这个节奏。

## 5. 匹配主键与标签

**宠物类型 × 时段 × 区域**（"12 月 伦敦 猫 代喂"）。

- 标签按接的类型打：`#宠物 #代喂 #寄养 #猫 #狗`；需求侧 `#求代喂 #猫`；
- 中英变体各写一次：catsitting / petsitting / 喂猫 / 代喂，多词连写；
- 时段词进标题（"圣诞假期"）——回国潮里这是第一搜法。

## 6. 描述骨架

```
首段（接头关键信息行，固定顺序）：
  形态+宠物限制——计价行——可接时段——区域
次段：频次 · 报平安约定 · 特殊情况接否 · 寄养环境
尾段：#标签
```

样例：
> 上门代喂，只接猫——计价：£8/次，每日一次；喂药 +£2/次——12 月圣诞假期
> 全程可接——南伦敦 Zone 2–3。每次上门发照片+视频报平安；自养布偶三年，
> 铲屎换水陪玩都做。#代喂 #猫 #catsitting #圣诞

## 8. 合规与照片检查

- 🔴 **活物责任线**：宠物生病、意外、走失的责任划分**双方线下自定**，
  平台不担保、不仲裁——agent 最多建议"喂药、送医这类事出发前当面说清，
  留一个兽医联系方式"；不替任何一方承诺"绝对安全"；
- **钥匙交接安全**：代喂涉及把家门钥匙交给陌生人（与上门服务卡（card-homeservice.md）入户安全同源、
  方向相反）——双向自行核实身份；交接方式提了必写、不主动展开；
- 报酬线下结算，平台不碰钱；
- 照片过 intake.md §4（`photo upload` 之前）：宠物照本身低敏，重点是
  **需求侧"我家猫"照片背景里的家庭环境**——门牌、窗外定位地标、屏幕入镜常查；
  且需求帖天然公开"家中无人"的时段信息，位置写**区域级即可**
  （本卡对 §4"精确到楼"默认口径的例外），精确楼栋接头后私聊；
- 报平安照片是接单后的私下约定，不经平台。
