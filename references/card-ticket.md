# 要素卡：转票（card=`TICKET`）

## 1. 归属与徽章

| | 供给侧（我出票） | 需求侧（我收票） |
|---|---|---|
| 覆盖 | 演出 / 球赛 / 火车票转让 | 收票 / 求票 |
| 徽章 | **转票** | **收票** |
| tradeType | SELL | BUY |

## 2. 要素三态表

| 档 | 供给侧 | 需求侧 |
|---|---|---|
| 🔴 必须成立 | 票名（演出/艺人/球队/车次线路）+ **场次日期时间**、币种 | 要什么票 + 场次窗口（"12 月哪场都行"也算成立）、币种 |
| 尽量抽取 | 座位/视野（"看台东侧""**非 restricted view**"——线上真实卖帖在写，买票人第一疑虑）、张数、电子/纸质 | 预算、张数 |
| 提了必写（绝不主动问，出现必落位） | 🔴 **使用条件**——railcard 绑定、限运营商、实名/换票要求：线上收票真实帖明着要求"请注明是否绑定 railcard"——绑定票对没卡的人是废纸，这一句省一整轮问询；票面价 | 应答要求（"来询请带座位截图"） |
| 提了才写 | 转手原因（"去不了了"一句即可） | 座位偏好（"最好连座"=软偏好，原样带上不追问） |
| 禁问 | 为什么去不了的细节、票哪来的 | 预算合理性不评价 |

## 3. 价格语义与计价行

**一口价实物逻辑**，无计价行——一张票一个价；多张票逐张列价
（沿用 card-goods.md §6 分件清单约定：一行一张、行首编号、卖掉标 ❌已出）。
票面价提了必写——"票面 £45 出 £30"是转票帖最有力的一句话；不评价挂价高低。
需求侧 `--price` = 预算上限（每张口径，多张写清总价还是单价）。

## 4. 时间语义

🔴 **硬时间窗**：场次/发车时间就是帖子的死线——**场次一过 = 帖必作废，
直接建议下架**，不问"还出吗"（同 card-rental.md 需求侧口径）。
`--available-until` 填场次/发车日期（不用默认 +14 天）；供需同规则。

## 5. 匹配主键与标签

**演出名/艺人/球队/车次线路 × 日期**。

- 艺人/球队名中英各写一次（周杰伦 Jay Chou / 阿森纳 Arsenal），多词连写；
- 日期进标题（"12.14 场"）——收票的人按场次搜；场馆名进描述；
- 标签：`#转票 #演唱会 #球票 #火车票` + 艺人/球队短词（需求侧 `#收票`）。

## 6. 描述骨架

```
首段：票名——场次日期时间+场馆——座位/视野——价格（带票面价对照）
次段：使用条件（railcard/限运营商/实名换票）· 交付方式（电子转赠/纸质面交/PDF）
尾段：#标签
需求侧：要什么票+场次窗口——预算/张数——应答要求（提了才写）——#标签
```

## 7. 确认门回显行

票名｜场次日期时间｜张数｜座位/视野｜价格（+票面价）｜交付方式｜使用条件
（火车票缺此项标注"收票帖明着在要这句——写了省一轮问询"，不追问）｜照片状态。
点头才发；需求侧发布后照 card-goods.md §7 固定反查在售（有现票当场推荐）。

## 8. 合规与照片检查

- **可转让性平台不核实不背书**：实名票、条款禁止转售的风险由双方自担；
  "可转让/可改名"是卖家自述，agent 不核查主办方条款、不替任何一方打包票；
- 不碰钱：电子票转赠与付款的先后顺序双方自行商定，agent 转述卖家条件，
  不设计担保/定金方案（同 card-goods.md 【交易】行纪律）；
- 🔴 照片检查重点（本帖型特有）：票面截图的**二维码/条码/booking reference
  必须遮**——出票码泄露 = 票被人先用；持票人姓名、订单号同查。
