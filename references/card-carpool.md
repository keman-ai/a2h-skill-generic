# 要素卡：拼车·接送机（card=`CARPOOL`）

## 1. 归属与徽章

| | 供给侧（有车/有空位） | 需求侧（求拼/求接送） |
|---|---|---|
| 覆盖 | 拼车 / 接机 / 送机（订了车有空位挂出来） | 求拼车 / 求接机 / 求送机 |
| 徽章 | **拼车**（接送机形态可显**接送机**） | **求拼车**（接机形态显**求接机**） |
| tradeType | SELL | BUY |

- 标的是**一段行程里的座位**，时间窗比帮带更硬（到小时）；
- 线上实证**需求先行、供给未现**——本卡需求侧是常态方向；读侧遇"求"字
  一律按需求侧读（读侧容错口径同 marketplace.md §B）。

## 2. 要素三态表

| 档 | 供给侧 | 需求侧 |
|---|---|---|
| 🔴 必须成立（两侧镜像） | 起点/终点（机场按 §5 三写）、日期 + 大致时刻（时刻落位见 §4） | 同左 |
| 尽量抽取 | 可载人数、车型、分摊口径（说不清面议） | 人数、**行李量（几件几寸——"两个 28 寸"决定车型，接机场景的关键差异项）** |
| 强烈建议补充（卡上标理由，不追问） | — | 行李件数/尺寸缺失时："接机的车装不装得下全看行李，写了少一轮来回问" |
| 提了才写 | 可绕路范围、宠物/超大件可否、**等待时长/延误处理**（接机高频：航班延误等多久、超时怎么算） | 同行人情况、落地后去向细节、等待时长/延误处理（同左）、**宠物同乘**（镜像供给侧"宠物可否"） |
| 禁问 | 🔴 **航班号（禁问也禁记，见 §7/§8）**、为什么这个时间走、同行人是谁 | 同左 |

## 3. 价格语义与计价行

- **人均分摊价，且随拼到的人数浮动**——单一价格字段装不下，必走计价行（§A3 约定）：
  - 本卡标准例句：`计价：人均 £15，拼满 3 人走`；
  - `--price` 填**人均参考价**或留空面议；
- 读侧按结构转述（"人均 15，拼满 3 人才走"），**不把 `--price` 当包车总价**；
- 需求侧 `--price` = 愿出的人均分摊（或面议）；
- 话术只写"**分摊车费/油费**"——计价行绝不写成"包车报价"（合规边界见 §8）。

## 4. 时间语义

🔴 **全场最硬的时间窗**：精确到小时，出发/落地时刻一过帖**必然作废**——
开场巡查不问"还卖吗"，直接建议下架。

🔴 **时刻只能进描述首行**：`--available-until` 仅日期粒度（评估实证），
装不下"14:30 落地"——日期填 `--available-until`，**时刻固定写在描述首段
第一行**，读侧从首行取时刻。

🔴 **读侧兜底：首行取不到时刻就全文扫**——上面那条是**写侧**约束（管住自己发的帖），
存量转载帖的描述首行清一色是导入器写的「价格：面议。」，真实时刻埋在摘要中段
（"19:30""晚 8 点"）。首行没有时刻时**通读全文找**，找到照常按硬时间窗对日期；
全文都没有才按"抠不出来的照常推荐"处理。

开学季（接机）是脉冲式高峰，帖生命周期普遍只有几天——建档时把
"过时即建议下架"预告给主人。

## 5. 匹配主键与标签

**机场/路线 × 日期**（"8.15 LHR""盖特威克到 UCL"），时刻不参与检索。

- 🔴 **机场词三写**：代号 + 两种中文译名各写一次——标题/正文带
  `LHR 希斯罗 希思罗`，**Heathrow 进标签**。检索实测：Heathrow 是死词
  （字级模糊匹配下英文全称搜不到人也没人搜）；希斯罗/希思罗两种译名
  **桥接不完全且排位靠后**（实搜「希斯罗」已能召回「希思罗」帖，但排位靠后），
  三写保排位、保全捞；
- 其他机场同理：LGW 盖特威克/盖特维克、STN 斯坦斯特德；
- 日期进标题（"8.15 LHR 求接机"）——同 card-errand.md 的日期检索口径；
- 标签：`#拼车 #接机`（送机 `#送机`）+ 英文机场词（`#Heathrow`）；
- 搜法配方（读侧）：机场各写法 × 月日词 × 形态词（拼车/接机/送机）混排；
- 「送机」单独作形态词搜噪音极大（实测 131 条结果几乎全是"送显示器/送咖啡机"
  的赠送帖）——优先用**机场词 × 日期**组合，「送机」只作辅助词。

## 6. 描述骨架

```
首段第一行（固定）：日期 + 时刻 + 起终点
  （"8.15 约 14:30 落地希斯罗（希思罗）T5 → UCL 主校区"）
首段续：计价行——人数——行李量
次段：车型 · 可绕路 · 同行说明（提了才写的落这）
尾段：#标签
```

仿真样例（需求侧，验收基准）：
> **8.15 LHR 求接机 到 UCL**
> 8.15 约 14:30 落地希斯罗（希思罗）T5 → UCL 主校区。计价：人均分摊车费，面议。
> 2 人，两个 28 寸 + 两个登机箱。
> #拼车 #接机 #Heathrow

## 7. 确认门回显行（接头卡）

起终点（机场三写状态）｜日期+时刻（时刻确认在描述首行）｜人数｜
行李量（缺=卡上标"建议补：车型全看它"）｜计价结构｜照片状态。

🔴 主人口述里带了航班号 → **不落帖、不入档**，回显时明确说明：
"航班号我没写进帖子也没记录——日期+时刻+航站楼已能反查到个位数航班，
公开挂出去等于公开你的行程。" 这是全卡体系唯一的**丢弃型**敏感例外——压过"口述落位零丢失"
工序的敏感例外**——丢弃是刻意的，必须让主人知道为什么。

## 8. 合规与照片检查

- 🔴 **航班号禁问也禁记**：不问；主人顺口报了也不落帖不入档（回显话术见 §7）；
- **私人成本分摊 ≠ 营运**：话术只写"分摊车费/油费"，agent 不替任何一方安排
  商业包车、不撮合以营利为目的的载客——这条边界保住产品不碰运输牌照问题。
  🔴 **读侧同款**：识别为商业包车广告的帖（"包车接送机·华人老司机"这类挂公司/
  常年接单/明码服务价的，线上确有实例）**不纳入推荐**——不是它违规，是撮合它
  等于我们在替营运拉客；主人点名问起时如实说明这条帖是商业服务、我们不背书；
- **安全自负**：司机/车辆/保险平台一概不核实，不说"靠谱""放心"类担保词；
- **不碰钱**：分摊结算线下自行处理；
- 照片：车牌、行程单/机票截图（**含航班号**——本卡禁记的信息不该从图里漏出去）
  入镜必查，打码或不传；
- 开学季联动（毕业三连的镜像）：求接机 + 求短租 + 落地置办常是同一新生
  同一周的事——接机帖建档顺口问"落地要不要看看在售的置办清单"，
  与 card-rental.md 的毕业清屋联动互为镜像。
