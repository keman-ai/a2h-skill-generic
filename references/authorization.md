# 🤝 一揽子授权剧本（authorization）

> 首次托管时对齐一次，之后整批适用。目标：**一条消息说完，用户回一个"行"就完成**。
> 授权协议**在当轮会话内成立**并复述给主人确认，不落盘——下次会话按本节重新对齐一次；
> MVP 阶段授权不含自动降价（任何改价必经用户确认）。

## 1. 首次对齐（30 秒版）

托管清单确认后，发**一条**消息，默认值全部给好，用户只需回"行"或改一两处：

> 那我按这个方式帮你卖，有不合适的直接说：
>
> - **卖法**：随缘卖——按清单价挂，合理还价我直接答应，不来烦你；
> - **白送线**：低于 ¥10 的东西直接送人不讲价；
> - **交付**：自提（回龙观）或邮寄到付，别的方式我会先问你；
> - **找你的时候**：只有收钱、约交接、出幺蛾子这三种事才找你，其他我自己处理。
>
> 没问题回个"行"，想改哪条直接说（比如"那个 Kindle 别贱卖"）。

规则：
- **一条消息、四个条款、全部带默认值**——不逐条提问，不开选择题；
- 用户回"行"/"可以"/"OK" → 协议成立，**复述一句确认**，开始上架；
- 用户改某条 → 改后**复述一句**确认（"好：Kindle 按稍等档，其他照旧"），不重新走全流程；
- 底价规则不在消息里展开（属于档位定义，见 pricing.md），用户问才解释。

## 2. 单件例外

识别用户对单件的特殊意愿，映射到档位/参数，**当轮记住，并在托管清单/回执上体现出来**——
让主人看得见，而不是存起来：

| 用户说 | 映射 |
|--------|------|
| "这件别贱卖 / 我还挺喜欢的" | 该件 → 稍等档 |
| "这个赶紧出掉 / 送人也行" | 该件 → 快清档，可白送 |
| "3 号 50 就行" | 挂价=50，底价按档位比例调整 |
| "那个别卖了" | 下架（集市状态→已下架） |

例外只影响该件，总协议不变。

## 3. 协议变更（任何时候一句话）

- "以后都快清" / "白送线改成 20" → 更新**当轮协议** → 复述一句确认；
- **生效规则：只影响未来动作，不追溯已谈定的交易**——已和买家谈定价格/交付的订单按谈定执行，未谈定的在售商品按新协议继续；
- 变更涉及在售商品挂价调整时（如整体降档），列出将改价的清单让用户过目后才改（改价必经确认）。

## 4. 授权边界速查（写给 agent 自己）

| 自主（不请示） | 必请示 |
|--------------|--------|
| 底价之上答应还价、成交 | 低于底价且买家坚持 |
| 好主人让价至底价 / 低价件提议送（快清/随缘） | 稍等档超 10% 的还价 |
| 白送线以下直接送 | 任何改挂价 |
| 按协议交付方式约交接 | 授权范围外的交付方式 |
| 失联超时回滚状态、候补递补 | 交付后纠纷、未注明瑕疵的售后 |
